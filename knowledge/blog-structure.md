# 博客结构与写作要点

更新：2026-10-24。依据当前仓库配置和正式文章整理，项目升级后需重新核对配置。

## 这个博客的定位

站点“翞~涵”记录日常、学习和折腾过程，也关注 Web 安全、比赛 WP 与复盘。文章适合用第一人称写真实经历，兼顾个人表达和可复用的信息。

技术文章让读者能跟着做，生活文章让读者看见具体的人和事。分类、网页版式、文字风格分开选择，不能只靠一个 `type` 代表三者。

## 文件与页面结构

| 位置 | 用途 |
| --- | --- |
| `content/posts/<年份>/*.md` | 正式文章 |
| `content/previews/` | 组件等预览示例，不作为作者个人文风样本 |
| `blog.config.ts` | 站点信息、分类、版式类型、链接规则 |
| `content.config.ts` | 内容集合和元数据校验 |
| `scripts/new-blog.ts` | `pnpm new` 新建文章脚本 |
| `app/components/content/` | 提示框、表格、图片等 Markdown / MDC 组件 |
| `knowledge/` | 写作规范与风格索引，不直接作为文章发布 |

当前使用 Nuxt、Nuxt Content 和 Clarity 主题。页面会渲染文章标题、摘要、正文目录及页脚，因此正文通常从导语或 `##` 开始，无须重复一个同名一级标题。

当前 `hidePostPrefix: true`，常规文章链接隐藏 `/posts`；也支持用 `permalink` 指定链接。引用旧文章时核对实际路径，不要根据中文标题自行猜 URL。

## 分类、版式和文风

配置中已有分类：技术、开发、安全、杂谈、生活，另有默认“未分类”。按文章主要内容选择；标签标记具体工具、比赛或主题，避免把分类全复制一遍。

网页版式只有两个现成选项：

- `tech`：默认版式，标题带技术文的标记，适合步骤和代码。
- `story`：标题居中、偏衬线字体，段落有首行缩进，适合叙事。

`A / B / C / D` 是[文风指南](blog-style-guide.md)中的写作代号，不填入 `type`。例如复盘可以选“安全”分类，用 D 风格；分析为主时配 `tech`，经历为主时配 `story`。

## 元数据模板

```yaml
---
title: 用具体的问题或经历命名
description: 一句话说明这篇讲什么、能得到什么
date: 2026-10-24 10:00:00
updated: 2026-10-24 10:00:00
type: tech
categories: [技术]
tags: [建站, Vercel]
---
```

时间使用 Asia/Shanghai。改旧文保留 `date`，按实际修改时间更新 `updated`。封面有合适图片再加 `image`；`recommend` 在当前 schema 中是数字，如 `recommend: 1`，不要继续照抄旧文里的布尔值。`references` 支持 `title`、`link` 组成的列表，会在页脚显示。

上述字段按文章实际需要填写，`draft` 标记也不能当成私密存储方式。正文、图片和凭据都应按实际发布链路检查。

## 通用写作约定

1. 开头两三段交代起因、目标和本文范围，少铺背景。
2. 一节完成一个任务，二级标题组成主线，三级标题只拆必要子步骤。不要每句话都单独起段或加标题。
3. 技术教程按依赖顺序写；步骤中保留必要条件和成功标志，把集中排障放到后面。同一个提醒只讲一次。
4. 日常表达可以有“折腾”“踩坑”和少量自嘲，但不能把情绪写成技术结论，也不堆梗。
5. 区分亲历、推测和文档事实。不要为了故事补造日期、奖项、对话、队友行为、排障过程或运行结果。
6. 费用、额度、界面字段和版本要求等易变信息先核对官方来源，必要时标日期；把限制写清，不靠“完全免费”“一定能用”下结论。
7. 收尾落在结果、真实感受或下一步行动，避免反复概括和硬升华。

## 排版和压缩

- 表格用于配置、对比和清单，不把整段文字塞进只有一个单元格的表格。
- 命令标明适用环境，给出预期结果；占位符、域名和桶名先统一说明。不要默认让读者执行覆盖文件等有损操作。
- 普通补充用正文或短引用；需要强调的重要提醒才用 MDC `::alert{type="warning"}`，并用独立一行 `::` 闭合。
- 加粗只留给关键值或结论；删除线、颜文字和感叹号少量点缀，不作为每节的固定装饰。
- 精简时先删重复解释、机械过渡和多余提醒，再合并碎段。保留前提、关键步骤、验证方式和必要来源。

提交前检查元数据类型、标题层级、代码块和 MDC 闭合、表格结构、内部链接及敏感信息。纯文字修改优先做 Markdown 解析和差异检查，不必机械地跑完整站点构建。
